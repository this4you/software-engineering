# Лабораторна робота: Основи Docker і контейнери для навчання

## Мета

Познайомитися з Docker на практиці. Ти власноруч запускаєш контейнери з
готових образів, керуєш їхнім життєвим циклом, заглядаєш усередину, розбираєшся
з портами, томами (volumes) і змінними середовища. У другій частині вчишся
головному практичному трюку: за кілька хвилин піднімати готові сервіси —
базу даних і веб-клієнт **Adminer** для роботи з нею через браузер, **без**
встановлення чогось на свій комп'ютер. Саме це знадобиться тобі в курсовому
і в будь-якому навчальному проекті.

> Це обіцяна окрема тема по контейнерах (про неї згадувалося в LR-22). Свій код
> писати **не потрібно** — усі дії виконуються в терміналі та браузері.

## Передумови

- Встановлений і **запущений Docker Desktop** (macOS / Windows / Linux).
  Перевір: `docker version` має показати і Client, і Server.
- Базові навички роботи з терміналом.
- (Для Частини 2) Скопійований стартер `lr23-starter/` — посилання дасть викладач.

> **Що таке Docker одним абзацом.** *Образ (image)* — це «заморожений» шаблон
> з програмою та всім, що їй потрібно (ОС-оточення, бібліотеки). *Контейнер
> (container)* — це **запущений екземпляр** образу, ізольований процес на твоїй
> машині. З одного образу можна запустити скільки завгодно контейнерів. Образи
> лежать у реєстрі **Docker Hub** (hub.docker.com), звідки Docker сам їх качає.

## Як здавати

- **Формат:** один файл `lab_docker_<прізвище>.md` або PDF — **тільки скріни**
  виконаних кроків з короткими підписами. Відповідати на питання й заповнювати
  чек-листи не треба — головне, щоб ти руками пройшов(ла) всі команди.
- **Скріни** вставляй у MD синтаксисом `![підпис](images/файл.png)` або просто
  прикріпи зображення по порядку.
- На кожному скріні має бути видно **команду в терміналі та її результат**
  (або вікно браузера з URL).
- **Здача:** як домовлено з викладачем (Google Classroom / пошта / Moodle).

# Частина 1 — Основи Docker

Виконуй команди по черзі й роби скрін після кожного завдання.

---

## Завдання 1 — Перший контейнер

**Що зробити:**
1. Перевірити, що Docker працює:
   ```bash
   docker version
   docker info
   ```
2. Запустити перший у житті контейнер:
   ```bash
   docker run hello-world
   ```
   Docker не знайде образ локально, скачає його з Docker Hub і запустить —
   у виводі буде привітання «Hello from Docker!».

**Що включити у звіт:**
- Скрін виводу `docker run hello-world`.

**Самоперевірка (для себе):** у виводі видно рядок `Hello from Docker!`.

---

## Завдання 2 — Запуск веб-сервера і проброс порту

**Що зробити:**
1. Запустити веб-сервер nginx у фоні з пробросом порту:
   ```bash
   docker run -d -p 8080:80 --name my-nginx nginx
   ```
   - `-d` — detached, контейнер працює у фоні;
   - `-p 8080:80` — порт `8080` твоєї машини → порт `80` всередині контейнера;
   - `--name my-nginx` — зручне ім'я замість випадкового.
2. Подивитися список запущених контейнерів:
   ```bash
   docker ps
   ```
3. Відкрити в браузері **http://localhost:8080** — має з'явитися сторінка
   «Welcome to nginx!».

**Що включити у звіт:**
- Скрін `docker ps` із контейнером `my-nginx`.
- Скрін сторінки nginx у браузері (видно URL `localhost:8080`).

**Самоперевірка:** сторінка nginx відкривається; у `docker ps` є запис із
портом `0.0.0.0:8080->80/tcp`.

---

## Завдання 3 — Заглянути всередину: логи та exec

**Що зробити:**
1. Подивитися логи nginx (звернення до сервера):
   ```bash
   docker logs my-nginx
   ```
   (Оноови сторінку в браузері кілька разів і знову подивись логи — з'являться
   нові рядки запитів.)
2. Зайти **всередину** запущеного контейнера, ніби по SSH:
   ```bash
   docker exec -it my-nginx sh
   ```
   Опинившись усередині, виконати:
   ```sh
   ls /usr/share/nginx/html
   cat /etc/os-release
   exit
   ```
   `exit` повертає тебе назад на свою машину.

**Що включити у звіт:**
- Скрін виводу `docker logs my-nginx`.
- Скрін сесії всередині контейнера (видно вивід `cat /etc/os-release` —
  яка ОС живе в контейнері).

**Самоперевірка:** `exec` не створив новий контейнер — ти зайшов(ла) у той самий
`my-nginx` (його видно в `docker ps`).

---

## Завдання 4 — Життєвий цикл і прибирання

**Що зробити:**
1. Зупинити контейнер і переконатися, що він **зник з `docker ps`**, але
   лишився в `docker ps -a`:
   ```bash
   docker stop my-nginx
   docker ps
   docker ps -a
   ```
2. Запустити його знову й знову зупинити:
   ```bash
   docker start my-nginx
   docker stop my-nginx
   ```
3. Видалити контейнер, потім подивитися наявні образи й видалити образ nginx:
   ```bash
   docker rm my-nginx
   docker images
   docker rmi nginx
   ```

**Що включити у звіт:**
- Скрін, де поряд видно порожній `docker ps` і непорожній `docker ps -a`
  (зупинений контейнер ще існує).
- Скрін `docker images` до або після видалення.

**Самоперевірка:** ти розумієш різницю: `stop` — призупиняє, `rm` — видаляє
контейнер, `rmi` — видаляє образ.

---

## Завдання 5 — Персистентність даних (volume)

Контейнери **ефемерні**: видалив контейнер — зникли всі дані всередині нього.
Щоб дані жили окремо від контейнера, їх кладуть у **том (volume)**.

**Що зробити:**
1. Запустити контейнер, підмонтувавши папку зі своєї машини всередину:
   ```bash
   docker run -it --rm -v "$(pwd)/mydata":/data alpine sh
   ```
   (Windows PowerShell: `docker run -it --rm -v "${PWD}/mydata:/data" alpine sh`)
2. Усередині створити файл і вийти:
   ```sh
   echo "Привіт з контейнера" > /data/hello.txt
   ls /data
   exit
   ```
3. Контейнер уже видалено (`--rm`), але на твоїй машині з'явилася папка
   `mydata` з файлом `hello.txt`. Перевір:
   ```bash
   cat mydata/hello.txt
   ```

**Що включити у звіт:**
- Скрін, де видно, що файл `hello.txt` залишився на машині **після** того, як
  контейнер припинив існувати.

**Самоперевірка:** дані пережили контейнер завдяки `-v` (volume mount).

---

## Завдання 6 — Конфігурація через змінні середовища

Контейнери налаштовують ззовні через **змінні середовища** (`-e`), а не
правлячи код усередині образу.

**Що зробити:**
1. Запустити контейнер, передавши свою змінну:
   ```bash
   docker run --rm -e MY_NAME="<твоє ім'я>" alpine sh -c 'echo "Привіт, $MY_NAME!"'
   ```
2. Подивитися всі змінні середовища всередині контейнера:
   ```bash
   docker run --rm -e MY_NAME="test" alpine env
   ```

**Що включити у звіт:**
- Скрін з виводом, де контейнер привітав тебе по імені (значення прийшло
  ззовні через `-e`).

**Самоперевірка:** ти змінив(ла) поведінку контейнера, не чіпаючи образ.

# Частина 2 — Docker для навчання: база даних + Adminer

Найкорисніше на практиці: підняти повноцінну базу даних і зручний веб-клієнт
до неї за хвилину, нічого не встановлюючи в систему.

---

## Завдання 7 — Підняти PostgreSQL у контейнері

**Що зробити:**
1. Запустити Postgres, задавши пароль через змінну середовища:
   ```bash
   docker run -d --name my-postgres \
     -e POSTGRES_PASSWORD=secret \
     -e POSTGRES_DB=studentdb \
     -p 5432:5432 \
     postgres:16
   ```
   (Windows PowerShell — у один рядок, без `\`.)
2. Переконатися, що база жива, зайшовши в неї клієнтом `psql` усередині
   контейнера:
   ```bash
   docker exec -it my-postgres psql -U postgres -d studentdb -c "SELECT version();"
   ```

**Що включити у звіт:**
- Скрін `docker ps` із контейнером `my-postgres`.
- Скрін виводу `SELECT version();` (база відповіла).

**Самоперевірка:** база працює, хоча Postgres ти на машину не встановлював(ла).

---

## Завдання 8 — Adminer: робота з базою через браузер

**Adminer** — легкий веб-інтерфейс для будь-якої бази (Postgres, MySQL, та ін.).

**Що зробити:**
1. Підняти Adminer окремим контейнером:
   ```bash
   docker run -d --name my-adminer -p 8081:8080 adminer
   ```
2. Відкрити **http://localhost:8081**. На формі входу ввести:
   - **System (Рушій):** PostgreSQL
   - **Server (Сервер):** `host.docker.internal` *(так контейнер Adminer
     бачить інші контейнери; на Linux, якщо не спрацює — використай IP машини
     або об'єднай контейнери, як у Завданні 9)*
   - **Username:** `postgres`
   - **Password:** `secret`
   - **Database:** `studentdb`
3. Після входу: створити таблицю (Create table), наприклад `students`
   з полями `id` і `name`, додати 2–3 рядки (Insert) і виконати запит
   `SELECT * FROM students` (вкладка SQL command).

**Що включити у звіт:**
- Скрін форми входу Adminer із заповненими полями.
- Скрін з результатом `SELECT * FROM students` (видно додані рядки).

**Самоперевірка:** ти створив(ла) таблицю й дані через браузер, без жодного
встановленого SQL-клієнта.

---

## Завдання 9 — Увесь стек однією командою: `docker compose`

Запускати контейнери поодинці й вручну зв'язувати — незручно. **Docker Compose**
описує весь набір сервісів в одному файлі `docker-compose.yml` і піднімає його
однією командою. Це **головний інструмент** для швидкого підняття оточення.

**Що зробити:**
1. Спочатку прибрати контейнери з попередніх завдань, щоб звільнити порти:
   ```bash
   docker rm -f my-postgres my-adminer
   ```
2. У папці `lr23-starter/` (зі стартера) лежить готовий `docker-compose.yml`
   (Postgres + Adminer). Підняти весь стек однією командою:
   ```bash
   docker compose up -d
   ```
3. Подивитися, що піднялося:
   ```bash
   docker compose ps
   ```
4. Відкрити Adminer **http://localhost:8081**. Цього разу в полі **Server**
   вказати просто `db` — усередині Compose сервіси бачать один одного за
   іменами. Зайти з тими ж логіном/паролем (див. `docker-compose.yml`).
5. Зупинити й прибрати весь стек однією командою:
   ```bash
   docker compose down
   ```

**Що включити у звіт:**
- Скрін `docker compose ps` із двома сервісами (`db` і `adminer`).
- Скрін успішного входу в Adminer із `Server = db`.

**Самоперевірка:** ти підняв(ла) базу + клієнт **однією** командою — саме так
зручно піднімати оточення для курсового чи будь-якого навчального проекту.

# Частина 3 — Бонусне завдання (опціонально)

Без нього лаба теж зарахована. Зроби, якщо хочеш покопатися глибше.

Зайди на **hub.docker.com**, обери будь-який інший готовий сервіс і підніми
його контейнером. Ідеї:
- `redis` + `redis/redisinsight` — кеш-сховище з веб-інтерфейсом;
- `mongo` + `mongo-express` — NoSQL-база з веб-клієнтом;
- `mysql` + `phpmyadmin` — альтернатива зв'язці з Завдання 8;
- будь-який готовий демо-застосунок.

**У звіт:** скрін запущеного сервісу (термінал або браузер) і 1–2 речення,
чим він міг би стати в пригоді тобі в навчанні.

# Поради

**Як зробити скрін:**
- macOS: `Cmd + Shift + 4` (виділена область) або `Cmd + Shift + 5`.
- Windows: `Win + Shift + S` (інструмент «Знімок екрана»).
- Linux (GNOME): `Shift + PrintScreen`.

**Якщо щось не працює:**

1. **`docker: command not found` або `Cannot connect to the Docker daemon`.**
   Не запущений Docker Desktop — відкрий застосунок і дочекайся, поки іконка
   стане «зеленою», тоді повтори команду.

2. **`port is already allocated` / порт зайнятий.** Інший процес (або старий
   контейнер) уже слухає порт. Прибери старі контейнери `docker rm -f <name>`
   або заміни ліву частину порту: напр. `-p 8082:80` замість `-p 8080:80`.

3. **Adminer не бачить базу (Завдання 8).** Поле **Server**: на macOS/Windows
   спробуй `host.docker.internal`. Якщо не виходить — зроби Завдання 9 через
   Compose, там сервіси бачать одне одного за іменем (`db`).

4. **Забув(ла) ім'я/ID контейнера.** Подивись `docker ps` (запущені) або
   `docker ps -a` (усі). Зупинити та видалити одразу: `docker rm -f <name>`.

5. **Контейнер одразу падає (`Exited`).** Подивись причину: `docker logs <name>`.

6. **Прибрати все за собою після лаби:**
   ```bash
   docker compose down
   docker rm -f my-nginx my-postgres my-adminer
   ```

Якщо нічого не допомогло — питай викладача, прикріпивши скрін помилки і
вивід `docker ps -a`.

Удачі!
